# Threat Model — Pixelated Empathy

## Authentication Boundary

- **Auth0** is the sole production identity provider (OIDC + PKCE).
- Auth middleware (`apps/web/src/middleware.ts`) validates session cookies on protected routes.
- API auth middleware (`apps/web/src/api/middleware/auth.ts`) validates bearer tokens via `authenticateRequest`.
- Admin routes require `role: 'admin'` enforced by `auth0-middleware.ts` RBAC checks.

## PHI Data Flows

- **Client → API**: Messages, session notes, and journal entries are sent over HTTPS.
- **API → PostgreSQL**: PHI stored in encrypted columns via `EncryptionManager` (AES-256-GCM with key rotation).
- **API → Presidio**: Inbound text is scanned for PHI entities by `PresidioPHIDetector` before storage.
- **PHI Detection**: Fail-closed — when Presidio is configured but not initialized, non-empty input is blocked.
- **Logging**: Structured logging via `build-safe-logger` avoids logging PHI payloads. Request/response bodies are never logged.

## E2E Test Bypass Lifecycle

- **Activation**: Only when `E2E_TEST_AUTH=1` env var is set (CI-only, never in production).
- **Token**: A per-run random token (`E2E_TEST_TOKEN`) is generated by the CI test harness and injected as both the password and cookie value. No literal credentials are committed.
- **Issuance**: `POST /api/auth/signin` accepts `test@example.com` + the E2E_TEST_TOKEN value, issues `auth-token=<E2E_TEST_TOKEN>` cookie.
- **Validation**: `middleware.ts` checks `auth-token=<E2E_TEST_TOKEN>` cookie, creates a short-lived (1h) admin session.
- **Teardown**: Token is unique per CI run, cannot be replayed, and is never set in production environments.

## Cryptographic Operations

- **Random generation**: `getRandomBytes()` and `generateRandomBytes()` require `crypto.getRandomValues`. No Math.random fallback — throws if unavailable.
- **Key IDs**: `EncryptionManager` uses `secureRandomString()` for key IDs, not `Math.random()`.
- **Secrets**: `SecretsManager` uses Web Crypto for random byte generation with no insecure fallback.

## Known Security Decisions

- **DOMPurify**: Content sanitization at render layer, not via regex blocklist in schemas.
- **Parameterized queries**: SQL injection prevention via parameterized queries, not regex filtering.
- **Trivy gate**: CI fails on CRITICAL/HIGH vulnerabilities (exit 1).
- **Fail-fast DB init**: Production startup aborts if MongoDB, PostgreSQL, or Redis are unavailable.

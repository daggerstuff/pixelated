# Struct Build Agent - Custom Prompts for Pixelated

Copy these prompts into **Settings → Coding Agent → Struct → Custom Prompts** in the Struct web app.

---

## Prompt 1: Coding Conventions

```
This is the Pixelated Empathy codebase - a therapeutic training and conversational analysis platform.

Stack:
- Frontend: Astro 5 + React 19 + TypeScript (strict mode)
- Backend: Express.js + Hono
- Python AI pipelines (bias detection, therapy evaluation)
- Databases: MongoDB, Redis, PostgreSQL
- Package managers: pnpm (Node), uv (Python)

Key patterns:
1. **Type Safety**: Use strict TypeScript. No `any` unless explicitly justified.
2. **No Suppression Comments**: Never use `// @ts-ignore`, `# noqa`, `/* eslint-disable */`.
   - Exception: `# type: ignore[import-untyped]` for missing third-party stubs with reason.
3. **Therapeutic Context**: Preserve therapeutic and privacy context in user-facing output.
4. **No Context-Mode Workflows**: Do not use `context-mode` or `context-mode_*` workflows.
5. **Verification**: Always verify behavior before declaring completion.
6. **File Organization**:
   - `src/`: Astro + React app, routes, shared TypeScript libraries
   - `ai/`: Python AI code (own commit discipline)
   - `scripts/`: Launcher and deployment helpers
   - `tests/`: Integration, browser, security, and API tests
   - `.agent/internal/`: Durable private docs, plans, and runbooks

Testing:
- Unit: `pnpm test:unit` (vitest with coverage)
- Integration: `pnpm test:integration`
- E2E: `pnpm e2e` (Playwright)
- Bias Detection: `pnpm test:bias-detection`
- Security: `pnpm security:check`

Commits: Conventional Commits format (feat:, fix:, chore:, refactor:, docs:, test:)
```

## Prompt 2: Architecture Context

```
Architecture Patterns:
1. **MCP Integration**: Uses Model Context Protocol for AI model communication
   - Main integration: `src/lib/api/mcp-integration.ts`
   - Memory transport: `src/lib/server/mcp-memory-transport.ts`
   - Foresight MCP: `scripts/memory/foresight-mcp-server.sh`

2. **Authentication**: JWT-based with Phase 6 integration
   - Phase 6 service: `src/lib/mcp/phase6-integration.ts`
   - Events: authentication_success, token_validated, etc.

3. **AI Services**: Modular Python services
   - Bias Detection: `src/lib/ai/bias-detection/`
   - Training Server: `src/lib/services/training/`
   - Academic Sourcing: `ai/academic_sourcing/`

4. **Memory System**: Foresight MCP for persistent agent memory
   - Database: `.foresight/memory.db`
   - Tools: manage_memories, search_memories, query_entities, etc.

5. **Database Migrations**: `scripts/db-migrate.ts` with status/rollback support

6. **Redis**: Hardened configuration with health checks
   - Scripts: `scripts/check-redis-hardening.sh`, `scripts/redis.sh`

7. **Security**:
   - No credentials in code/logs/tests/commits
   - HIPAA compliance validation
   - Trivy scanning in CI
   - Checkov infrastructure scanning

Important Files:
- `.github/copilot-instructions.md` - Copilot guidance
- `CLAUDE.md` - oh-my-claudecode configuration
- `AGENTS.md` in ai/ and foresight-mcp/ for sub-agent instructions
```

## Prompt 3: Testing Requirements

```
When implementing fixes, ensure:
1. All existing tests pass (`pnpm test`)
2. TypeScript compiles without errors (`pnpm typecheck`)
3. Linting passes (`pnpm lint:ci:with-markdown`)
4. Code is formatted (`pnpm format:check:changed`)
5. For security fixes: `pnpm security:check`
6. For bias detection changes: `pnpm test:bias-detection`

Test file locations:
- Unit: `src/**/*.test.ts`, `src/**/*.spec.ts`
- Integration: `tests/integration/`
- E2E: `tests/e2e/`, `tests/browser/`
- Bias Detection: `src/lib/ai/bias-detection/`, `src/components/admin/bias-detection/`
- Python: `tests/test_*.py`, `ai/**/tests/`
```

## Prompt 4: Common Fix Patterns

```
1. **Type Errors**: Add proper types, avoid `any`. Use type guards for runtime validation.
2. **Lint Errors**: Fix the underlying issue, don't disable rules.
3. **Test Failures**: Update tests to match new behavior, don't skip tests.
4. **Build Failures**: Check Docker build, dependency versions, Node version (>=24).
5. **Security Issues**: Run `pnpm security:check` to validate no credentials leaked.
6. **Performance**: Use `pnpm performance:test` for regression checks.
```

## Prompt 5: Security & Privacy

```
CRITICAL - Never include in code, logs, tests, or commits:
- Credentials (API keys, passwords, tokens)
- Patient data or PII
- Therapeutic session content
- Any sensitive healthcare information

Always:
- Use environment variables for secrets
- Run `pnpm security:check` before committing
- Preserve therapeutic context in user-facing output
- Follow HIPAA compliance patterns
```
